VLAN Hopping Attacks

A VLAN hopping attack enables traffic from one
VLAN to be seen by another VLAN without the aid
of a router. In a basic VLAN hopping attack, the
threat actor configures a host to act like a switch to
take advantage of the automatic trunking port
feature enabled by default on most switch ports.
The threat actor configures the host to spoof
802.1Q signaling and Cisco-proprietary Dynamic
Trunking Protocol (DTP) signaling to trunk with the
connecting switch. If successful, the switch
establishes a trunk link with the host, as shown in
the figure. Now the threat actor can access all the
VLANs on the switch. The threat actor can send
and receive traffic on any VLAN, effectively hopping
between VLANs.

VLAN Double-Tagging Attacks

A threat actor is specific situations could embed a hidden 802.1Q tag inside the frame that already has an 802.1Q tag. This tag allows the frame to go to a VLAN that the original 802.1Q tag did no specify.

Step 1:
The threat actor sends a double-tagged 802.1Q frame to the switch. The outer header has the VLAN tag of the threat actor, which is the same as the native VLAN of the trunk port.

Step 2:
The frame arrives on the first switch, which looks at the first 4-byte 802.1Q tag. The
switch sees that the frame is destined for the native VLAN. The switch forwards the packet out
all native VLAN ports after stripping the VLAN tag. The frame is not retagged because it is part
of the native VLAN. At this point, the inner VLAN tag is still intact and has not been inspected
by the first switch.

Step 3:
The frame arrives at the second switch which has no knowledge that it was supposed
to be for the native VLAN. Native VLAN traffic is not tagged by the sending switch as specified
in the 802.1Q specification. The second switch looks only at the inner 802.1Q tag that the threat
actor inserted and sees that the frame is destined the target VLAN. The second switch sends
the frame on to the target or floods it, depending on whether there is an existing MAC address
table entry for the target.

basically, adds a VLAN tag to send traffic on the native VALN.

Solution

Access ports

  1. take everything off of VLAN 1
  2. BLACK-HOLE all unused ports
    • if it has no cable it is unused
  3. do this with all access ports
  4. use #show_commands show int status to check

Trunks

  1. make it statically a trunk switchport mode trunk
  2. disallow the BLACK-HOLE and VLAN 1 on the trunk
  3. Disable DTP switchport trunk nonegotiate
  4. use #show_commands show int trunk to check
  5. use #show_commands show run to check for DTP

MAC Address Table attack

  • attackers flood the mac add table to break it
  • this is just access ports

All MAC tables have a fixed size and consequently, a switch can run out of resources in
which to store MAC addresses. MAC address flooding attacks take advantage of this
limitation by bombarding the switch with fake source MAC addresses until the switch MAC
address table is full.
When this occurs, the switch treats the frame as an unknown unicast and begins to flood
all incoming traffic out all ports on the same VLAN without referencing the MAC table.
This condition now allows a threat actor to capture all of the frames sent from one host to
another on the local LAN or local VLAN.
Note: Traffic is flooded only within the local LAN or VLAN. The threat actor can only capture traffic
within the local LAN or VLAN to which the threat actor is connected.

Solution

  • table limit
  • mac filtering

access ports

  • enable port security switchport port-security
  • switchport port-security mac {static or sticky}
    • static - config a specific mac
    • sticky - dynamically learn and save to running config - faster boot
  • switchport port-security max {maximum number of MAC addresses accepted by the switchport}
  • switchport port-security violation {protect / restrict / shutdown}
    • Restrict - notifys you and starts dropping frames
    • protect - no notificat and just dropps frames – worst option
    • shutdown - as implied
  • switchport port-security aging time {Minutes when MAC addresses are deleted from the port in the table}
    • Aging is Absolute by default
    • Packet Tracer only allows you to set the time in minutes
