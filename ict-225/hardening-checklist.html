Finger is a protocol that allows for a client to query human readable information about a user or system. Finger is no longer used as obtaining information about a user/system is a security risk. Disable bootstrap protocol Legacy – not needed and removed to reduce attack vectors

Layer 2 Threat Mitigation

Configuration Task Description/Rationale Configuration Complete
Dynamic ARP Inspection Prevents ARP spoofing during MiTM attacks by verifying ARP messages. REQUIRES DHCP SNOOPING <br><br>ip arp inspection vlan 10,20,30 <br><br>On Trusted Interfaces: <br><br>ip arp inspection trust
DHCP Snooping Prevents a rogue DHCP attack by scanning for rogue servers and blocking their traffic. It also prevents DHCP starvation attacks by scanning for large amounts of IP requests coming from the same MAC and verifying said MAC. ip dhcp snooping <br><br>ip dhcp snooping vlan 10,20,30 <br><br>ip dhcp snooping verify mac <br><br>Trusted Interfaces: <br><br>ip dhcp snooping trust <br><br>Untrusted Interfaces: <br><br>ip dhcp snooping limit rate 6
IP Source Guard Provides source IP address filtering. Prevents a threat actor from spoofing a legitimate host by using a legitimate host IP. Uses DHCP snooping and static IP source binding to match IP addresses to hosts on untrusted Layer 2 access ports interface ### <br><br>ip verify source <br><br>exit <br><br>ip source binding <MAC> vlan <VLAN ID> <IP> interface <INT ID> <br><br>FOR SWITCHES CONNECTED TO STATIC HOSTS: <br><br>ip device tracking <br><br>interface ### <br><br>ip verify source {tracking\|mac-check} <br><br>ip device tracking maximum {0-10} N/A
STP Security (PVSTP/Portfast/BDPUGuard/
RootGuard/LoopGuard)		 PortFast + BPDU Guard or Rootguard can be used to prevents MiTM attacks that take over the STP topology to change the root bridge. 

Loopguard prevents a STP blocking/listening port from transitioning to another STP state when it stops receiving BPDUs and creating a loop. Loopguard does this by placing these ports into a loop-inconsistent state when they stop receiving BPDUs 

PVST runs a separate instance of STP for each VLAN configured on the device. This is done to allow for logical separation and increased efficiency for STP.		 On all access ports: <br><br>spanning-tree portfast <br><br>spanning-tree bpduguard enable <br><br>On trunks: <br><br>spanning-tree rootguard <br><br>On non-designated trunk ports: <br><br>Spanning-tree loopguard default <br><br>PVST: <br><br>spanning-tree mode pvst <br><br>spanning-tree vlan <id> priority <int>
MAC-based Port Security Prevents MAC Address Table attacks by only allowing a certain amount of MAC’s from each port or restricting traffic from a port to only a s couple of specific MAC’s. On all access ports: <br><br>switchport nonegotiate <br><br>switchport mode access <br><br>switchport port-security <br><br>switchport port-security maximum 4 <br><br>switchport port-security violation shutdown <br><br>switchport port-security aging time 10
DTP Security 

VTP Security		 Disables DTP and prevent DTP messages from being generated 

Configures trunk ports to use a dedicated Native VLAN 

VTP (VLAN Trunking Protocol) is a protocol that allows a switch to connect to a VTP server and receive information about VLANs (compared to manual configuration on each switch).		 Configure Access ports <br><br>Configure Trunk ports <br><br>Create dedicated Native VLAN: <br><br>vlan 99 <br><br>name Native <br><br>Configure Trunk ports to use Native VLAN: <br><br>switchport trunk native vlan 99 <br><br>Run “switchport nonegotiate” on all trunk and access ports <br><br>vtp mode transparent
Unused Port Security Shutdowns unused ports and takes them off the default VLAN (VLAN 1). This prevents a threat actor from being able to use the port to access the network. Create a dedicated “Blackhole” VLAN: <br><br>vlan 666 <br><br>name Blackhole <br><br>Set all unused ports to access and shut them down: <br><br>switchport mode access <br><br>switchport access vlan 666 <br><br>shutdown
