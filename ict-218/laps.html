LAPS

1. Introduction to LAPS

What Problem Does LAPS Solve?

Traditionally, many organizations use the same local Administrator password on multiple computers.

Risks

  • Attackers who compromise one workstation can obtain the local administrator password.
  • The same password may work on many systems.
  • Enables lateral movement throughout the network.
  • Increases the impact of credential theft.

Example

An attacker compromises a user's workstation and extracts the local Administrator password. If the same password exists on 500 computers, the attacker can access all those systems.

Windows LAPS Solution

Windows LAPS automatically:

  • Generates unique passwords for local administrator accounts.
  • Rotates passwords regularly.
  • Stores passwords securely in Active Directory or Microsoft Entra ID.
  • Controls password access through permissions.

2. What is Windows LAPS?

Windows LAPS is Microsoft's built-in password management solution for local administrator accounts.

Main Capabilities

Password Management

  • Automatic password generation
  • Randomized passwords
  • Scheduled password rotation

Password Protection

  • Secure storage
  • Access control
  • Password expiration enforcement

Administrative Control

  • Centralized management
  • Group Policy support
  • PowerShell management tools

3. Windows LAPS Architecture

High-Level Architecture

Architectural Components

1. Managed Device

Examples:

  • Windows 11
  • Windows Server 2025

Responsibilities:

  • Generate secure passwords
  • Track password expiration
  • Encrypt password data
  • Upload password information

2. Local Administrator Account

Can be:

  • Built-in Administrator account
  • Custom administrator account

LAPS manages:

  • Password creation
  • Rotation schedule
  • Password expiration

3. Active Directory

Stores:

  • Password information
  • Expiration timestamps
  • Authorization information

Provides:

  • Centralized storage
  • Access control
  • Auditing

4. Domain Controllers

Domain Controllers:

  • Authenticate requests
  • Store LAPS attributes
  • Apply permissions
  • Replicate data across the domain

5. Group Policy

Used to configure:

  • Password length
  • Complexity
  • Rotation frequency
  • Encryption settings
  • Backup destination

6. Password Lifecycle

Step 1: Policy Application

Group Policy defines:

  • Password length
  • Password age
  • Password complexity rules

Example:

  1. Length: 14 characters
  2. Expiration: 30 days
  3. Complexity: Enabled

Step 2: Password Generation

Device generates:
1 a9#Tx4!LmP8$qW

Characteristics:

  • Random
  • Unique
  • Strong entropy

Step 3: Password Storage

Password is stored in:

  • Active Directory
  • Microsoft Entra ID (optional)

Password information can be encrypted before storage.

Step 4: Password Retrieval

Authorized administrator retrieves password using:

  • Windows Admin Center
  • PowerShell
  • Active Directory tools

Step 5: Password Rotation

When expiration date is reached:

  • New password generated
  • Old password replaced
  • AD updated automatically

5. AD Schema Integration

What is the AD Schema?

The Active Directory schema is the blueprint that defines:

  • Object classes
  • Attributes
  • Rules for storage

Examples:

  • User objects
  • Computer objects
  • Security groups

Why Does LAPS Need Schema Changes?

Active Directory must have a location to store:

  • Password information
  • Expiration metadata
  • Encryption data
    Microsoft added new attributes specifically for Windows LAPS.

6. LAPS Schema Attributes

Windows LAPS extends the schema by adding attributes to computer objects.

Common Attributes

  • Password Attribute stores:
    • Current managed password
  • Password Expiration Attribute stores:
    • Password expiration timestamp
  • Encryption Metadata stores:
    • Encryption-related information
  • Recovery Data used for:
    • Authorized password retrieval
    • Auditing
    • Recovery operations

7. Schema Extension Process

Administrative Requirements

You must be:

  • Enterprise Admin
  • Schema Admin

Extend the Schema

PowerShell Command: 

Update-LapsADSchema

Purpose:

  • Adds LAPS attributes
  • Updates AD schema
  • Prepares AD for password storage

Verification

Verify extension: 

Get-LapsADSchema

Check that:

  • Attributes exist
  • Schema updates succeeded

8. AD Permission Model

LAPS security depends heavily on permissions.

Principle of Least Privilege

Only authorized personnel should:

  • View passwords
  • Reset passwords
  • Configure policies

Permission Delegation

Grant password access: 

Set-LapsADReadPasswordPermission

Example Groups:

  • Domain Admins
  • Help Desk
  • Security Operations Team

Password Reset Delegation

Set-LapsADResetPasswordPermission

Allows:

  • Forced rotation
  • Emergency remediation

9. Password Encryption in AD

Traditional LAPS Limitation

Legacy Microsoft LAPS:

  • Stored password as plain text attribute
  • Relied primarily on AD permissions

Windows LAPS Enhancement

Windows LAPS supports:

  • Password encryption
  • Authorized decryption
  • Improved security

Benefits:

  • Reduced insider threats
  • Better compliance
  • Stronger credential protection

10. AD Replication and LAPS

How Replication Works

When a password changes:

  1. Client updates AD.
  2. Domain Controller stores password.
  3. Password attribute replicates.
  4. Other Domain Controllers receive update.

Why Replication Matters

Benefits:

  • High availability
  • Disaster recovery
  • Administrator access from any site

11. Security Benefits of LAPS

Mitigates Pass-the-Hash Attacks

Because each computer uses:

  • Different Password
    Compromising one password does not compromise others.

Reduces Lateral Movement

  • Attackers cannot reuse credentials across systems.

Limits Credential Exposure

Passwords:

  • Rotate automatically
  • Expire regularly
  • Are centrally managed

Supports Compliance

Useful for:

  • CIS Controls
  • NIST Framework
  • ISO 27001
  • Government security standards

12. Windows Server 2025 LAPS Deployment Process

  1. Extend AD Schema: `Update-LapsADSchema
  2. Configure Organizational Unit permissions: `Set-LapsADComputerSelfPermission
  3. Delegate password access: `Set-LapsADReadPasswordPermission
  4. Create Group Policy Settings, configure:
    • Password age
    • Password length
    • Encryption
    • Managed account
  5. Apply Policy: `gpupdate /force
  6. Verify Configuration `Get-LapsPolicy
  7. Retrieve Password: `Get-LapsADPassword

Real-World Case Study

Scenario

  • A company manages:
    • 2,000 workstations
    • 150 servers
  • Before LAPS:
    • All systems shared one local administrator password.
  • Security Incident:
    • Malware compromised one workstation.
    • Local administrator credentials were stolen.
    • Attackers moved laterally across multiple systems.
  • After Windows LAPS Deployment:
    • Every device had a unique password.
    • Passwords rotated every 30 days.
    • Help Desk staff received delegated read permissions.
    • Security team maintained auditing.
  • Result:
    • Lateral movement was significantly reduced.
    • Administrative password management became centralized.
    • Compliance audit findings were resolved.

Best Practices

  • Use Password Encryption
    • Always enable password encryption when supported.
  • Limit Password Readers
    • Follow least privilege principles.
  • Rotate Frequently
    • Recommended:
      • Workstations: 30 days
      • Sensitive Servers: 7-14 days
  • Monitor Access
    • Review:
      • Password retrieval events
      • Permission changes
      • Failed access attempts
  • Use Dedicated Administrative Accounts
    • Avoid using personal user accounts to retrieve LAPS passwords.

Lecture Summary

Windows LAPS is a critical security feature in Windows Server 2025 that automatically manages
local administrator passwords. By integrating directly with Active Directory through schema
extensions, LAPS provides centralized password storage, automatic rotation, encryption,
delegation, and auditing. Proper implementation helps prevent credential theft, pass-the-hash
attacks, and lateral movement while supporting modern security frameworks and Zero Trust principles.

Key Takeaways for Students

  • LAPS solves the shared local administrator password problem.
  • Every managed computer receives a unique password.
  • Active Directory stores LAPS password information using schema extensions.
  • Domain Controllers replicate password information securely.
  • Permission delegation controls who can view passwords.
  • Windows LAPS supports encryption and auditing.
  • LAPS significantly reduces lateral movement and credential-based attacks.
  • LAPS is a recommended security control for all Windows Server 2025 environments
