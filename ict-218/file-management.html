File Management

Learning Objectives

By the end of this chapter, students should be able to:
• Create and manage file shares.
• Configure share and NTFS permissions.
• Automate drive mappings using Group Policy and Intune.
• Implement Distributed File System (DFS).
• Configure DFS Replication (DFSR).
• Deploy FTP services.
• Implement SMB over QUIC for secure remote file access.
• Apply file server security best practices.

1. Why File Management Matters

Company data is one of the most valuable assets in any organization.

Examples include:

• Financial records
• Human resources documents
• Customer information
• Project files
• Shared departmental resources

A Windows File Server provides a centralized location for storing, accessing,
securing, and backing up this data.

Discussion Question

What would happen if a company lost access to its file server for one day?

Expected answers:

• Productivity loss
• Revenue impact
• Lost customer confidence
• Possible compliance violations

2. File Shares

What is a File Share?
A file share is a folder made available over the network.

Example:

\\FS01\Accounting

Users connect to the share and access files based on assigned permissions.

Best Practice

Store data on a separate volume instead of the C: drive.

Example:

D:\Accounting
D:\HR
D:\Public

This improves:
• Organization
• Performance
• Backup management

Creating a Share

Steps:

  1. Create a folder.
  2. Open Properties.
  3. Select Sharing.
  4. Select Advanced Sharing.
  5. Share the folder.
  6. Configure permissions.

Windows creates a network-accessible resource.

Viewing Shares

Administrators can view shares using:

  • Computer Management
Computer Management
└ Shared Folders
└ Shares
  • UNC Path
    \SERVERNAME

Example:
\\FS01
This displays all accessible shares.

3. Mapping Network Drives

Users often prefer a drive letter rather than a UNC path.

Example

Instead of:
\\FS01\Sales
Map the share as:
S:

Command-Line Mapping

net use S: \\FS01\Sales /persistent:yes

Explanation:
• S: = drive letter
• /persistent:yes = reconnects at login

Important

SNMB needs permissions for security on the network.

Benefits

• Easier access
• Consistent drive assignments
• Reduced support calls

4. Automated Drive Mapping

Managing hundreds of users manually is not practical.
Windows supports automation.

Group Policy Drive Mapping

Location:
User Configuration
└ Preferences
└ Windows Settings
└ Drive Maps

Benefits:

• Central management
• Easy updates
• Automatic deployment

Administrators can map departmental drives without touching individual PCs.

Intune Drive Mapping

Useful for remote and cloud-managed devices.

Advantages:

• Works outside the corporate network
• Supports hybrid environments
• Centralized management from Microsoft Intune

Organizations increasingly use Intune for modern device management

5. Understanding Permissions

Permissions determine who can access data.
There are two permission layers:

Share Permissions

Applied when connecting through the network. –simple network share.
Common settings:
• Read
• Change
• Full Control

NTFS Permissions

Applied directly to files and folders.
Common settings:
• Full Control
• Modify
• Read & Execute
• Read
• Write
Both permission systems work together.

Question: Share Permissions: Full Control for user1, NTFS (Security) Permission,
Read for user1. What’s the result?

user1 only has read

6. Permission Best Practices

Use Security Groups

Do not assign permissions directly to users.
Instead:

  • assign permissions to groups
    • Folder-Accounting-ReadOnly
    • Folder-Accounting-ReadWrite
  • Assign users to groups.

Benefits:
• Easier administration
• Better auditing
• Less configuration effort

Deny Always Wins

Example:

  • User belongs to:
    • Sales-Users
  • which has:
    • Allow Read
  • User also belongs to:
    • RestrictedUsers
  • which has:
    • Deny Read
  • Final result:
    • Access Denied
      Because Deny overrides Allow.

7. Permission Inheritance

Permissions are inherited from parent folders.

Example:

D:\Data
├─Accounting
├─HR
└─Projects
Permissions assigned to Data automatically flow to child folders.

Benefits:

• Simplifies administration
• Improves consistency

Breaking inheritance should only occur when necessary.

8. Effective Access

Administrators often ask:
"Why can this user access this folder?"
or
"Why is this user denied?"
Use:
Folder Properties
└ Security
└ Advanced
└ Effective Access
This tool calculates actual permissions for a user or group.

9. Distributed File System (DFS)

Problem:

  • If users map directly to \\FS01\Accounting
  • and the server changes to \\FS02\Accounting
  • all mappings must be updated.

DFS Solution

  1. Create a namespace \\contoso.local\Files
  2. Users always connect to \\contoso.local\Files\Accounting
  3. DFS redirects them to the actual server.

Benefits of DFS

• Simplified administration
• Easier migrations
• Improved scalability
• Consistent user experience

10. DFS Replication (DFSR)

DFS Replication copies files between servers automatically.

Example - 2 servers:

FS01
↕
FS02

Files remain synchronized.

Replication Topologies

Full Mesh
Every server talks to every other server.
A ↔ B
↕ ↕
C ↔ D
Best for small environments.

Hub and Spoke

Branch1
|
Branch2--Hub--Branch3
|
Branch4
Best for larger environments.

DFSR Benefits

• Fault tolerance
• High availability
• Multi-site support
• Automated synchronization

11. FTP Services

FTP allows file transfers between systems.

Common use cases:

• Legacy devices
• External partners
• Manufacturing systems
• File exchange services

FTP Variants

  • FTP
    • Runs on Port 21
    • No encryption
    • Not recommended for sensitive data
  • FTPS
    • FTP + SSL/TLS
    • Encrypted
    • More secure
  • SFTP
    • SSH File Transfer Protocol
    • Runs on Port 22
    • Uses SSH
    • Most secure option

FTP Installation

  1. Install:
    Web Server (IIS)
    └ FTP Server
  2. Then configure:
    • FTP site
    • Authentication
    • SSL settings
    • Firewall rules
      Testing can be performed with WinSCP.

12. SMB over QUIC

Traditional Remote Access Problem, users often need:

  • VPN connection
  • SMB access through corporate network
    VPNs increase complexity and support requirements.

SMB over QUIC Solution

SMB traffic is encapsulated in QUIC and TLS 1.3.

Benefits:

• No traditional VPN required
• Secure remote access
• Better user experience
• Internet-accessible file shares

Requirements

• Windows Server 2025
• TLS certificate
• Port 443 connectivity

Example Mapping

net use S: \\files.contoso.com\share /TRANSPORT:QUIC

This forces SMB over QUIC

13. Backup Strategy

Important principle:

  • Backups, backups, backups!

Even correctly configured file permissions cannot protect against:

  • Accidental deletion
  • Disk failure
  • Malware
  • Ransomware
    File servers require regular backups and recovery testing.

Student Takeaways

  1. File servers provide centralized storage and management.
  2. Share permissions and NTFS permissions work together.
  3. Use security groups instead of individual user permissions.
  4. Deny permissions override Allow permissions.
  5. DFS provides a single namespace for file access.
  6. DFS Replication keeps files synchronized across servers.
  7. FTP, FTPS, and SFTP provide file transfer capabilities.
  8. SMB over QUIC enables secure internet-based file access without a traditional VPN.
  9. Automated drive mappings reduce administrative effort.
  10. Regular backups are essential for protecting company data.
