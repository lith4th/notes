REVIEW

  • The Processor of a computer can be thought of as the "brain" of the computer

  • The primary function is to complete instructions from the Operating System

  • The Socket is the physical connector on the motherboard. Each Socket can hold a Processor. Often the terms Socket and Processor are used interchangeably

  • A Physical Processor/Socket can consist of one or more Physical Cores.

  • The more physical cores within a processor/socket, more sets of instructions can be completed faster and simultaneously (instructions can be completed faster with the more brains you have)

  • Generally, physical cores complete sets of instructions known as "threads"

  • A physical core can only complete one thread at a time

  • "Logical Processors" indicate how many threads a physical core can complete

  • 4 Physical Cores with 1 Thread per core = 4 Logical Processors

  • 4 Physical Cores with 2 Threads per core = 8 Logical Processors

  • Logical Processors = Cores x Threads

  • Logical Processors can be thought of as Threads per Core

  • There are new hybrid designs where not all cores have hyperthreading enabled

    • they can start alternating between threads while waiting for other processes.

  • Hyperthreading indicates that a core can work on multiple threads.

  • Cores can only work on 1 thread at a time, cores cannot work on all threads simultaneously.

  • When cores are waiting for instructions from the operating system for one thread, the core can switch to working on the other thread, "multitasking"

  • Hyperthreading does NOT double the performance!

  • Hyperthreading improves performance by about 10-15%

  • the reason not all cores may have hyperthreading is P an E cores

VIRTUAL PROCESSORS / VCPU'S

  • With Virtualization, a Type 1 Hypervisor manages the processor resources
  • Each Virtual Machine is assigned a certain number of Virtual Processors
  • Virtual Processors are also known as Virtual Central Processing Units (vCPU's)
  • The vCPU's are mapped to a logical processor
  • Thus, the logical processor can be split up between multiple vCPUs
  • Logical processor's capacity can be divided among the vCPUs as workload is required
  • You Cannot force a certain virtual processor to always map to / use the same logical processor. Logical processors on the host share the resources between virtual processors.

PROCESSOR SCHEDULING

  • When virtual processors need to process instructions the hypervisor assigns the virtual processor to an available logical processor

  • The issue is that the guest operating system on a virtual machine thinks it always has direct access to the physical processor of the host. And many virtual processors could be using the same logical processor on the host. Thus, hypervisors schedule when vCPUs can be provided with processing resources.

  • the OS may know that it is a VM but doesn't know how many other VM’s there are.

    • the VM could be greedy

2 Types of scheduling for hypervisors: Gang and Free Processor Scheduling

  1. Gang Scheduling
    • A VM with multiple vCPUs being scheduled to an available logical processor
    • All the vCPUs are scheduled together
    • Leads to delay and inefficiency
    • Dinner example from the text:
      • "Dinner with a group of friends. You sit down, open the menu, and know exactly what you want to eat. But have to wait for 15 minutes until everyone else has decided what they will order, because you have to all order at the same time."
      • you’re waiting for the host to say that you can order
  2. Free Processor Scheduling
    • Allows vCPUs to be scheduled only as they have workload
      • as needed basis
    • Dinner example from the text: "You can order dinner whenever you're ready!"

Hyper V uses Free Processor Scheduling

  • Because Hyper-V uses Free Processor Scheduling there is no specific "limit" to the number of vCPUs we can assign to a VM
  • However, there are best practices when assigning the number vCPUs to virtual machines

Best Practices

  • it is based on the number of physical cores on the hosts for the max that you are considering.
    • no more then there actually are.
  • in datacenters assume that hyperthreading is disabled
    • this is due to power consumption vs extra power.
  • always be as conservative as you can when it comes to resources.
    • assume it will sit at 80% of the processing power most of the time.

Limitations and best Practices

  • Vendor for a Hypervisor will state the max number of vCPUs that can be assigned to a single VM and/or total of vCPUs for all VMs on a single host

  • When creating virtual machines or servers in the field, vendors for their software will often provide specifications that are overprovisioned

  • (ie SolarWinds Monitoring and Reporting Software)

  • Try to provide just enough processing power (vCPUs) to virtual machines so they can handle the highest workload. Minimize the number of vCPUs per VM as much as possible

  • If a virtual machine is not performing well in an enterprise environment, simply adding resources like vCPU is not guaranteed to improve performance

  • Software on the server may only be using the first or second vCPU assigned on the VM, rather than using the other vCPUs assigned

  • Look back about 14-30 days to see if the vCPU % is consistently over 80% with monitoring software, or try to identify when and where the spikes were for processing

  • Sometimes a server just needs to complete a Restart to finish updating

Compatibility mode

  • Not possible to live migrate a virtual machine to a new physical host with a different model processor: Intel or AMD, very different architectures.
  • BUT you can export and import a VM to a new physical host with a different model processor when it's turned off during the export. Be very careful though! This will likely lead to performance issues on the new host!
  • Enabling this setting allows virtual machines to migrate between different versions of the same model processor easier
  • Hides higher-level features of a newer processor from the guest operating system
  • Does not scan for lowest common denominator or lowest common set of functionality, only limits the processor to a basic generic set.
Simply Put
  • live migration is not possible across different CPU architecture or versions
  • Live Migration fixes this
  • It hides new features of a processor from the guest OS
  • live migration cannot fix cross vendors
Question

True or False:
A guest VM running on a cluster node with an AMD processor can live migrate to a cluster node with an Intel processor.

Answer: False

Limitations And Best Practices

  • All nodes in a cluster (physical hosts) should have the same hardware specifications! This avoids issues with live migration of VMs!
  • Avoid enabling Compatibility Mode unless absolutely necessary because the physical hosts in a cluster have different versions of the model of the processor.
  • Software or operating systems often need the higher level functions of more powerful processors
  • A virtual machine using a different version of a processor will likely lead to performance issues. Use the same models of physical hosts whenever possible.
  • Exporting and Importing a virtual machine to a host with a different processor will work, however this will likely lead to performance issues.
  • Avoid setting reserves for virtual machines in data center environments. These reserved values are not recommended!
