Memory

Virtual Memory

Virtual locations (addresses) of memory on a virtual machine map to physical
locations (addresses) of memory on the physical host

Configuring Memory for virtual machines can be either

  • Static/Statically assigned
  • Dynamic/Dynamically Assigned
    • changes depending on workload

Startup RAM

  • this is how much RAM is needed from the host to start up.
  • it is how much you set.
  • same for both static and dynamic

Static Vs Dynamic

Static

Static Memory is "fixed." The VM will always have access to this set value of Memory regardless of whether it is actually used or not.

Always use Static Memory for Database (aka SQL) Servers! opManager is a Database Server!

Note

SQL is a RAM hog, it doesn't let go of the ram

VM automatically uses amount of Memory defined in Startup RAM setting

With Hyper-V, when static memory is in use, RAM can be added or removed manually as desired

But other Memory settings and features are disabled:

  • Minimum
  • Maximum RAM
  • Memory Buffer

Dynamic

Dynamic Memory allows a hypervisor to allocate memory to VMs based on their actual needs (workload needs)

Dynamic memory can be very useful because it will automatically adjust available memory for each virtual machine

With Dynamic Memory, VMs will start with a minimum amount of memory and can request more as their workloads demand it

The virtual machine won't start if the physical host cannot provide the initial startup memory resource

Dynamic in the VCS

For Dynamic Memory in Hyper-V, each virtual machine does have a Virtual Service Client (VSC) that communicates to a Virtual Service Provider (VSP)

The Virtual Service Client only reports its memory use and how much available memory it has.

The VSC for the virtual machine dedicated to memory does not make requests for memory resources like other VSCs make requests for networking and storage resources


Green = Ask
Yellow = Repot

The OS used something called a balloon driver to request more RAM by giving a report of what is in use.

The Hypervisor only knows how much is in use and how much can be reclaimed by the hypervisor. it cant see what is being run

Ballooning

Ballooning allows the guest operating system on a virtual machine decide which pieces of memory to reserve

Ballooning determines which pieces of memory are available for the hypervisor to remove and apply to another virtual machine

Without ballooning, the hypervisor might take pieces of memory that are currently in use, corrupting the virtual machine

Each virtual machine has a balloon driver installed on the guest operating system

Inflating - host is taking from VM

Hyper-V makes requests via the Balloon driver on virtual machines to return memory

Hyper-V gives guest operating systems to use their balloon driver to indicate which pieces of memory can be reclaimed the hypervisor

Balloon driver "inflates" to indicate which pieces of memory are not in use and can be detached from the virtual machine and returned

"Inflating" the balloon allows the hypervisor to reclaim memory from the virtual machine

Balloon driver targets free, cached, and unused, inactive application memory to give back to the hypervisor.

If the virtual machine has no available memory to give, it will start paging to free up memory for the hypervisor. this is because the Hypervisor is in complete control of memory and the VM doesn't get a choice.

Deflating - Host is Giving back to the VM

Deflating allows the virtual machine to reclaim memory from the physical host

If a guest operating system needs more memory from the physical host, the balloon driver will start to "deflate"

Balloon driver "deflates" to map be able to a physical location of memory on the host

Limitations and Best Practices

Older, legacy operating systems cannot really take advantage of dynamic memory because they were designed to use as little memory as possible

A virtual machine cannot be assigned more memory than the amount of physical memory present on the host

Avoid minimum reservations for virtual machines in data center environments. These reserve values are not recommended

Recommendation is to turn the virtual machine off when manually adding or removing static memory.

Always turn off the virtual machine when removing static memory.

Memory that is manually added cannot exceed what is available on the physical host

If a virtual machine is not performing well in an enterprise environment, simply adding resources like memory is not guaranteed to improve performance

  • Software on the server impacts memory usage and allocation
  • Look back about 14-30 days to see if the Memory % is consistently over 80% with monitoring software, or try to identify when and where the spikes were for memory processing
  • Sometimes a server just needs to complete a Restart to finish updating

With really solid planning and provisioning for your virtual machines and resource allocation, you should not have to use dynamic memory!

Use static memory for 100's / 100's virtual machines.

Vendor for a Hypervisor will state the max number of memory that can be assigned to a single virtual machine

  • (ie 1 TB for Hyper-V)

When creating virtual machines or servers in the field, vendors for their software will often provide specifications that are overprovisioned

  • (ie SolarWinds Monitoring and Reporting Software)

Try to provide just enough memory to virtual machines so they can handle the highest workload. Minimize the amount of memory per VM as much as possible

Virtual Machines Hosts that have nested virtualization enabled must have static memory assigned to the virtual machine host

For any type of database server using SQL (ie Microsoft SQL, PostgreSQL, MySQL, etc), always use static memory, rather than dynamic with a maximum limit.

Database servers will consume as much memory from the physical host as possible but will not allow the host to reclaim any memory if dynamic memory is enabled

Allow Database Analysts or Database Teams determine memory allocation and database settings for SQL servers
